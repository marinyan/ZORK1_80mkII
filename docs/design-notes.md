# 設計メモ

## 固定条件

- PC-8001mkIIの64KiB主RAMを使用する。
- テキスト表示を維持し、16KiBのGVRAMをデータ置き場として利用する案を検証する。
- テキストVRAM領域は表示用に確保する。
- 80S31は使用せず、ゲーム開始後のテープ再読み込みも前提にしない。
- 英語用Z-machineをそのまま収めることより、半角カナ用にデータ形式とパーサを縮小することを優先する。

## 原版Zork Iの規模

`references/zork1/COMPILED/zork1.z3`について確認した値:

| 項目 | サイズ |
|---|---:|
| Z-code全体 | 86,838 B |
| Dynamic memory | 11,282 B |
| Dictionary | 4,795 B |
| High memory | 67,554 B |
| High memory内のコード部分 | 50,888 B |
| 文字列部分 | 16,666 B |

原版Z-codeだけで本体の総物理メモリ量を超えるため、単純な一括展開では動作しない。

## Upkr実測

Upkr `v0.2.2`の`--z80`設定で原版`zork1.z3`を圧縮した結果:

| 方式 | 圧縮データ | 原寸比 | 索引込み概算 |
|---|---:|---:|---:|
| 一括・順方向 | 59,524 B | 68.55% | - |
| 一括・逆方向 | 59,037 B | 67.99% | - |
| 1KiB独立ブロック | 69,227 B | 79.72% | 69,737 B |
| 2KiB独立ブロック | 67,187 B | 77.37% | 67,445 B |
| 4KiB独立ブロック | 65,555 B | 75.49% | 65,687 B |
| 8KiB独立ブロック | 64,254 B | 73.99% | 64,320 B |
| 16KiB独立ブロック | 62,847 B | 72.37% | 62,883 B |

索引込み概算は、各ブロックに圧縮元アドレス、圧縮長、展開長を各16ビットで持たせた場合。

Z80展開器をsjasmplusで実際に組み立てた結果:

| 項目 | サイズ |
|---|---:|
| 順方向展開コード | 170 B |
| 逆方向展開コード | 167 B |
| 確率表 | 320 B |
| 必要スタック | 10 B |

確率表は256バイト境界へ配置する必要がある。原版全体を逆方向展開した場合、Upkrの`--margin`が報告した重ね書き余白は2バイトだった。

## 圧縮の使い分け

### 全体が収まる場合

日本語化、辞書縮小、不要機能削除の後でゲーム本体とエンジンを合わせて利用可能メモリへ収められるなら、逆方向の重ね書き一括展開を使う。展開後は圧縮データ領域をそのまま解放できる。

### 全体が収まらない場合

変更されない文章やコードを独立ブロックとして保持し、低位RAMのキャッシュへ必要時に展開する。Upkrはストリーム途中からのランダム展開ができないため、ランダムアクセス単位ごとに別々に圧縮する必要がある。

原版の静的領域だけを4KiB独立ブロックにすると、索引込みで58,389 Bになる。これにDynamic memory、キャッシュ、インタプリタ、テキストVRAMを加えるとまだ収まらないため、ブロック圧縮だけではなく日本語用データ構造への変更が必須。

## 暫定メモリ構成

正確な境界は実装後のサイズに応じて変更する。

| アドレス | 候補用途 |
|---|---|
| `0000-2BFF` | 可変ゲーム状態、オブジェクト状態 |
| `2C00-7FFF` | 辞書、パーサ、展開キャッシュ、圧縮データの一部 |
| `8000-BFFF` 主RAM | 圧縮データ |
| `8000-BFFF` GVRAM | 圧縮データの別バンク |
| `C000-F2FF` | 常駐エンジン、展開器、スタック |
| `F300-FEB7` | テキストVRAM |

GVRAMから展開するときは、常駐コードを`C000`以降に置き、展開先を`8000-BFFF`以外にする。GVRAM選択中に同じ窓の主RAMへ書くことはできない。

## 当面の縮小対象

- 半角カナ向け6ビット前後の文字コード
- 方角を`ｷﾀ`、`ﾐﾅﾐ`などで扱う日本語専用辞書
- 英語の活用・前置詞処理を除いた入力パーサ
- 頻出する助詞、語尾、定型文の辞書化
- セーブ、UNDO、VERIFYなど初期版で不要な機能
- 常駐させるホットコードと圧縮可能な低頻度コードの分離
